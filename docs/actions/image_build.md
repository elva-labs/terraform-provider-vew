# vew_image_build action

Starts one VEW image build for an existing pipeline, then waits for the image to
finish. Building an image may incur AWS charges. Declare the action and invoke it
explicitly when you intend to build; ordinary `terraform plan` and `terraform
apply` do not invoke a declared action.

## Configuration

| Attribute | Description |
| --- | --- |
| `project_id` | Project that owns the pipeline. Required. |
| `pipeline_id` | Existing pipeline to execute. Required. |
| `idempotency_key` | Caller-chosen RFC 4122 UUID for this logical build. Required. |
| `timeout_minutes` | Positive wait limit. Optional; defaults to 120 minutes. |
| `wait_for_completion` | Wait until the image is created. Optional; defaults to `true`. |

The client needs project assignment and the `clients/packaging/pipeline.execute`
scope to submit the build, plus `clients/packaging/pipeline.read` to poll it.
Pipeline write permission is not required for this action.

## Direct invocation

```hcl
action "vew_image_build" "example" {
  config {
    project_id       = "your-project-id"
    pipeline_id      = "your-existing-pipeline-id"
    idempotency_key  = "90827b61-8399-4d8a-9843-d75d1556fed0"
    timeout_minutes  = 120
  }
}
```

```shell
terraform init
terraform apply -invoke=action.vew_image_build.example
```

An invocation plan contains the action, not other pending resource changes.
The action reports the reserved VEW `imageId`, lifecycle transitions, and final
`imageUpstreamId` through Terraform progress messages. These are informational:
actions have no structured result or Terraform state that HCL expressions can
reference. Removing the action declaration makes no image API mutation and does
not undo an accepted build.

Keep the same `idempotency_key` in configuration after an interruption or
timeout and invoke again to recover the same logical build while VEW retains its
idempotency record. VEW retains completed replays for **at least 24 hours**;
reusing the key after that boundary is not guaranteed to prevent another build.
Choose a **new UUID key** only when you intentionally want another build.
Reusing one key with a different pipeline request can fail with a conflict.

The default wait is two hours. Set a larger positive `timeout_minutes` when a
pipeline can take longer; a timeout does not cancel an already accepted build.
Keep the key and invoke again to resume observation within the replay window.
Do not attach this action to `after_update`: editing a pipeline is not an
instruction to start another billable image build.

Set `wait_for_completion = false` to return as soon as VEW has accepted the
build. The build continues in VEW, and a long image build no longer holds the
Terraform run, or an HCP agent, for hours. Read the result from VEW on a later
run, for example through `vew_product_versions` for the product the pipeline
feeds. `timeout_minutes` is ignored without a wait.

## Schema

### Required

- `idempotency_key` (String) Caller-supplied RFC 4122 UUID. Reuse it when retrying the same build.
- `pipeline_id` (String) Pipeline used to build the image.
- `project_id` (String) Project containing the pipeline.

### Optional

- `timeout_minutes` (Number) Maximum time to wait for image creation, in minutes. Defaults to 120. Ignored when wait_for_completion is false.
- `wait_for_completion` (Boolean) Wait until the image is created (the default, true). With false the action returns once VEW has accepted the build; the build continues in VEW and its result is read from VEW (for example the product's versions) on a later run.
