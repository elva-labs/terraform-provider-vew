# vew_project_client_bootstrap (Action)

Explicitly grants a different management client access to an existing project
with no active service-client assignments. Configure a recovery provider alias
with `project_client_bootstrap = true` and the assignment-write and bootstrap
scopes. The action validates the returned assignment, makes no subsequent GET,
and has no managed resource state or destroy behavior.

Declaring the action does not invoke it. Preview and invoke it with:

```shell
terraform plan -invoke=action.vew_project_client_bootstrap.manager
terraform apply -invoke=action.vew_project_client_bootstrap.manager
```

After success, use the assigned management client's credentials for normal
assignment resources. Never target the recovery client itself. Bootstrap is
unavailable once any client has an active assignment. Uncertain requests are
not automatically retried: verify the manager's assignment before another
invocation. See the [project access guide](../guides/project-access.md) for
migration and recovery.

## Example Usage

```terraform
terraform {
  required_version = ">= 1.16.0"
  required_providers {
    vew = { source = "elva-labs/vew" }
  }
}

# Supply recovery credentials through VEW_* environment variables.
provider "vew" {
  alias                    = "recovery"
  project_client_bootstrap = true
}

variable "project_id" {
  type = string
}

variable "management_client_id" {
  type = string
}

action "vew_project_client_bootstrap" "manager" {
  provider = vew.recovery
  config {
    project_id = var.project_id
    client_id  = var.management_client_id
  }
}
```
