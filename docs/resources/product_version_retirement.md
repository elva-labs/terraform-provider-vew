# vew_product_version_retirement (Resource)

Retires a product version through the Publishing API: VEW unpublishes it from
every account it was distributed to, so it can no longer be launched or chosen
as an update target.

The provider must be configured with `publishing_api_url` or
`VEW_PUBLISHING_API_URL`; the caller needs an active assignment to the project
and the `clients/publishing/version.read` and
`clients/publishing/version.retire` scopes. VEW applies the same rules as in
the portal: the product's latest version can't be retired, and every
distribution of the version must be created.

Workbenches already on the version keep running and starting, but can no longer
change size until they are updated to another version. VEW therefore refuses
to retire a version that non-terminated workbenches are still on (`409
VERSION_IN_USE`), unless `force` is `true`.

Terraform waits until the version is retired in every account (30 minutes by
default, configurable with `timeouts.create`). A retirement that is still in
progress when the timeout expires stays in state and is reconciled by the next
apply. `project_id`, `product_id` and `version_id` force replacement; `reason`
and `force` are only sent when the retirement starts.

Destroying the resource only removes it from Terraform: VEW does not restore
the version. If the version is restored in VEW, the next plan shows the
retirement again.

## Example Usage

```terraform
terraform {
  required_providers {
    vew = {
      source = "elva-labs/vew"
    }
  }
}

provider "vew" {
  api_url            = "https://api.example.invalid/clients/packaging/v1"
  publishing_api_url = "https://api.example.invalid/clients/publishing"
}

# Withdraw an old version of a product once its users have moved on.
resource "vew_product_version_retirement" "example" {
  project_id = "project-example"
  product_id = "prod-example"
  version_id = "vers-example"
  reason     = "Superseded by 1.1.0"
}
```
