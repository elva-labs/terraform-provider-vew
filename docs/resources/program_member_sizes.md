# vew_program_member_sizes (Resource)

Grants one user, in one project, keys of the deployment's workbench size
catalog beyond the ones everyone may use: larger sizes (for example
`standard-m`, `standard-l`), GPU sizes (`gpu-s`, `gpu-m`, `gpu-l`, offered only
on GPU products) and larger disks (`disk-500`, `disk-1000`). VEW refuses a
launch or resize with a size or disk the user was not granted; a workbench
keeps the size it already has when a grant is narrowed.

Set `provisioning_api_url` (or `VEW_PROVISIONING_API_URL`) and grant the
provider client `clients/provisioning/workbench_size.read` and
`clients/provisioning/workbench_size.write`. The same grants can be set by the
project's admins in the portal (Administration > Access); manage a user in one
place. `project_id` and `user_id` are immutable. `sizes` replaces the user's
whole set; an empty set keeps the record with everyone's sizes, and destroy
removes it. Unknown keys, or keys everyone has anyway, are refused.

## Example Usage

```terraform
resource "vew_program_member_sizes" "engineer" {
  project_id = "proj-example"
  user_id    = "01234567-89AB-CDEF-0123-456789ABCDEF"
  user_email = "engineer@example.com"

  # Beyond everyone's (the catalog's alwaysAllowed sizes, for example a 4 vCPU size and a 250 GB disk).
  sizes = ["standard-m", "disk-500"]
}
```
