# vew_base_image_release (Resource)

Points one of the deployment's base-image channels at an image. A deployment
can configure channels per architecture (for example `test` and `prod`), each
with an OS entry that every project's recipes can build on. The release is how
a platform team ships a new golden image: VEW resolves a recipe's parent image
from the channel when a recipe version is created, so projects adopt a new
base with their next recipe version.

VEW decides which project may release (the image must be one of its builds
for that architecture) and which channel gates another: a `prod` release only
takes an image that is or was released to `test`. Changing `image_id`
releases the new image in place and keeps the replaced AMI as
`previous_ami_id`, so a rollback is a release of the older image.

Grant the provider client `clients/packaging/base_image.read` and
`clients/packaging/base_image.write`, plus an active assignment to the
releasing project. A base image is never withdrawn: destroy only removes the
resource from state and leaves the channel as it is.

## Example Usage

```terraform
terraform {
  required_providers {
    vew = {
      source = "elva-labs/vew"
    }
  }
}

provider "vew" {
  api_url = "https://api.example.invalid/clients/packaging/v1"
}

# The platform project releases a build to test first; prod only takes an
# image that is or was in test.
resource "vew_base_image_release" "test" {
  project_id   = "project-platform"
  architecture = "amd64"
  channel      = "test"
  image_id     = "image-example"
}

resource "vew_base_image_release" "prod" {
  project_id   = vew_base_image_release.test.project_id
  architecture = "amd64"
  channel      = "prod"
  image_id     = vew_base_image_release.test.image_id
}
```

## Schema

### Required

- `architecture` (String) The image architecture (for example amd64).
- `channel` (String) The channel (for example test or prod). VEW may require an image to pass another channel first.
- `image_id` (String) The VEW image to release. Changing it releases the new image in place; the replaced AMI is kept as previous_ami_id.
- `project_id` (String) The project allowed to release base images; the image must be one of its builds.

### Read-Only

- `ami_id` (String) The released AMI.
- `id` (String) The ID of this resource.
- `os_version` (String) The OS entry recipes select for this channel.
- `parameter_name` (String) The parameter VEW resolves the channel from.
- `previous_ami_id` (String) The AMI the last release replaced (rollback).
